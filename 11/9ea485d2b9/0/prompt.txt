# Investigate

A **router**, not a doer. When you have a question, this skill tells you which
source to reach for, in what order, and how to trust the answer. It points to
the dedicated per-tool skills you already have rather than repeating them — see
`references/sources.md` for the exact tools, commands, and gotchas per source.

The goal: **understand the real situation before you plan, fix, or write.** Most
wasted work comes from acting on an assumption that five minutes of research
would have corrected.

## Start here: orient before you act

Three things come before any routing below:

1. **Read the tied ticket first.** If a ticket exists for this task, read it
   before anything else. Identify it from the **ticket hint** above — admin
   branches embed the ticket ID (e.g. `user/BIG-123-short-title`) — or from what
   the user told you. If you can't identify it, **ask which ticket; don't
   guess.** Fetch it with Linear `get_issue` and let it anchor scope.
2. **Understand what's already changed.** Review the branch diff above. If it's
   non-trivial, read the actual diff before proposing changes — never treat the
   current file state as the baseline without checking what this branch did.
3. **Only then** route your remaining open questions through the table below.

## Discipline (applies to every source)

- **Fire research early, in parallel** with your first code reads — it costs
  almost no wall-clock and stops you building on a wrong assumption.
- **Triangulate.** Any claim that drives a decision gets confirmed across ≥2
  independent sources. Code tells you *what*; Unblocked/Slack/PRs tell you *why*.
- **Cite.** Keep the URL, PR number, `file:line`, or verbatim quote so a
  reviewer can check your reasoning — and so you can.
- **Three buckets, kept distinct:** stated fact · labeled inference · unknown.
  Never let an inference harden into a "fact."
- **Ask, don't assume.** When a material fact is missing and no tool can supply
  it, ask the user a specific question rather than inventing an answer.
- **Multi-modal.** One search angle is not enough. A local grep miss may just
  mean the code lives in an associated repo — try Unblocked code search before
  concluding something doesn't exist.
