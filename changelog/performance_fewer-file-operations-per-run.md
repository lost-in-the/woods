- Three per-file costs that scale with unit count rather than code shape, measured on an 11,000-unit app whose container filesystem made them 3–34× their testbed cost: (1) a full extraction no longer seeds the new payload with hardlinks to the previous generation's unit directories, since it rewrites every unit of every family it extracts and sweeps the rest (families the configuration gates out, such as `rails_source` with `include_framework_sources` off, are still carried forward); (2) the publication recheck reuses the capture's identity for any file whose device, inode, size, mtime and ctime are all unchanged, so an untouched tree is re-stat'd rather than re-hashed — a changed file, or a capture handed off from the launcher process, is hashed as before; (3) `AtomicFile.write` opens its temp file directly with the final permissions instead of through `Tempfile`, and creates a missing directory on demand rather than checking for it on every write: four system calls per file instead of eight. Published payloads are byte-identical.
