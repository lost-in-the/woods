- The Index Server names the index it serves. `initialize` instructions lead with the checkout (directory name and path), branch, generation number and `updated_at`, and the Woods build that wrote the index, followed by `WARNING:` lines for a checkout, branch or build mismatch. `woods_status` leads with an `identity` block carrying the same plus `client_matches` (the index's checkout versus the launcher's), `client_root`, `client_branch`, `branch_matches` and `build` (writer versus reader). Identity costs two small file reads before the handshake. See [served index identity](docs/MCP_SERVERS.md#served-index-identity).
- Manifests record the writer's git revision: `woods_revision` (the Bundler git source's locked revision, or `HEAD` of a checkout rooted at the gem root; `null` for a released gem), `woods_revision_dirty`, and the indexed application `root`. A reader at another version string says "Index written by Woods X, this reader is Y; run `woods:extract` or request a re-index."; one at the same version string but another revision says "Index written by a different Woods build (<rev>)". A read that fails a payload guard under such a gap answers with that message (`index_build_mismatch`) instead of `typed unit identity mismatch` / `corrupt_artifact`, and `woods_status.index.incremental` reports `cause: "build_mismatch"` with a `build mismatch (...)` status instead of "needs full extraction".
