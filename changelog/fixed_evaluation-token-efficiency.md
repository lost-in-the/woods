- `woods:evaluate` no longer reports unit precision as token efficiency. Each retrieval source now carries the estimated `tokens` of the text rendered for it (the truncated text when a unit was cut to fit), `token_efficiency` is the share of the context's `tokens_used` spent on expected units, and the old number survives as the new `unit_precision` metric (`mean_unit_precision` in aggregates and thresholds). When sources carry no token figure the score falls back to unit precision, and the per-query and report-level `token_efficiency_basis` fields say which basis produced it. A lone expected unit that rendered 50 of 8,000 tokens used to score 1.0 and now scores 0.00625. A thresholds file (`EVAL_BASELINE_FILE`) that gates on `mean_token_efficiency` was calibrated against the old unit-count number and will now fail: move that threshold to `mean_unit_precision`, or re-baseline it against the rendered-token share.
