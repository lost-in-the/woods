- A reference that appears only in a comment no longer produces a dependency edge. Every shared scan reads its source through `Woods::Extractors::CommentBlanking`: the model, service, job, mailer, navigation, and form scans of `SharedDependencyScanner`, `ReferencePatterns` (which `CallbackAnalyzer` and `JobExtractor` also use), the partial and route-helper scans of view templates, the interactor, API client, HTTP, and Redis scans of `ServiceExtractor` and `JobExtractor`, the configuration-file reads of `ConfigReadScanner` (`config_file` edges), the token fallback `ConstantPaths` uses for source Prism cannot parse, the request and host reads of `TestRouteResolver` (a trailing `# visit widgets_path` or a commented `host!` no longer decides a test's route edges), and the declaration and usage scans of `TestSupportCatalog` (a shared example, matcher, or helper named only in a comment is neither a `test_support` name nor a `test_support` edge; the published source keeps its comments). Ruby comments are found with Prism, so `=begin`/`=end` blocks are covered, and a `#` in a quoted string or an interpolation is still read as code. Heredoc text is prose as well: the YAML, SQL, or markdown body of a heredoc (such as a component's `translations <<~YAML`) no longer produces an edge, while a `#{...}` interpolation inside it still does. A heredoc whose body is Ruby is read whole: one tagged `RUBY` or `RB`, and one passed to `class_eval`, `module_eval`, `instance_eval`, or `eval`. Templates use their engine's comment forms: ERB `<%# ... %>` and `<% # ... %>`, HAML `-#` blocks and `- # ...` lines.
