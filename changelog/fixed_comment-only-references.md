- A reference that appears only in a comment no longer produces a dependency edge. Every shared scan reads its source through `Woods::Extractors::CommentBlanking`: the model, service, job, mailer, navigation, and form scans of `SharedDependencyScanner`, `ReferencePatterns` (which `CallbackAnalyzer` and `JobExtractor` also use), the partial and route-helper scans of view templates, the interactor, API client, HTTP, and Redis scans of `ServiceExtractor` and `JobExtractor`, the configuration-file reads of `ConfigReadScanner` (`config_file` edges), and the token fallback `ConstantPaths` uses for source Prism cannot parse. Ruby comments are found with Prism, so `=begin`/`=end` blocks are covered, and a `#` in a string, heredoc, or interpolation is still read as code. Templates use their engine's comment forms: ERB `<%# ... %>` and `<% # ... %>`, HAML `-#` blocks and `- # ...` lines.
