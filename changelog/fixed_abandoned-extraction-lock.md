- A writer killed mid-run (a container restart, `SIGKILL`, an OOM kill) no longer blocks the watcher and every other writer until `LOCK_STALE_TIMEOUT` passes. `extraction.lock` now records the holder's host beside its pid, and a lock written on this host by a pid that no longer exists is stale at once. Locks from another host, or written before the host was recorded, are still judged by age, since a pid cannot be checked across namespaces. A rake writer that has to wait now says so once, naming the holder's pid, host and lock time (`Waiting up to 600s for the extraction lock held by pid 123 on web-1 since …`), instead of waiting silently.
