- `Woods::MCP::Server.build` no longer warms the index reader and retriever before returning: `warmup:` now takes `:after_handshake` (the default, also `true`), `:before_handshake` or `:none` (also `false`). The packaged launchers (`woods-mcp`, `woods-mcp-start`, `woods-mcp-http`, `bin/woods-self-mcp`) use the default. An embedding that relied on `build` returning a warmed server passes `warmup: :before_handshake`, which warms synchronously and lets a warm-up exception propagate as before. Over stdio, run the built server through `Woods::MCP::StdioTransport` (both packaged stdio servers already do) so the warm-up starts only after the `initialize` response is flushed. Unknown `warmup:` values raise `ArgumentError`. A client of lexical `codebase_retrieve` can now receive a non-error `warming` result (`structuredContent.data.status: warming`, `retryable: true`, no sources) when it calls past `WOODS_MCP_HYDRATION_WAIT_SECONDS` during the startup warm-up; retry the call.
