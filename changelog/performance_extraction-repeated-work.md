- Extraction blanks a unit's comments once per run instead of once per scanner. The model-name, service/mailer/job reference, config-read and route-helper scans each re-walked the syntax tree and copied the source, up to eight times for a controller or component; the result is now kept in the run's parse cache (eight scans of a 1,500-line source: about 30 ms before, 9 ms after). A full extraction also no longer deep-copies the metadata of units that have no source references. Extraction output is unchanged.
- Within one incremental run, a type's `_index.json` is rebuilt from the entries the run already derived: a unit file whose bytes are unchanged is hashed instead of parsed and re-serialized. When a run rebuilds the same type's index more than once (controllers after the flow pass, for one), the later rebuilds reuse the entries. The directory listing still decides which units exist, and nothing is carried between runs. A table re-run also reads the published table units once instead of twice.
