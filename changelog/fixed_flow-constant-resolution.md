- Flows now follow rooted calls and no longer send a call on a top-level constant into an app class that shares its short name (#967). A rooted call such as `::Billing::Invoice.create!` was recorded with its leading `::` and then never resolved, so the step silently dropped out of the flow. A rooted name now matches its exact unit, from the graph or from disk, and never a unit of the same short name in another namespace. With `precompute_flows` on, a single-segment call target (`I18n.t`) that matches exactly one app unit by short name (`Lint::I18n`) while the booted app already defines a top-level constant of that name is now marked ambiguous, naming both candidates (`::I18n` and `Lint::I18n`), instead of expanding the app unit. The check reads `Object.const_defined?(name, false)` and never autoloads. The precompute publishes its verdicts in `flows/top_level_constants.json`, so `trace_flow` assembling a flow on demand without Rails reaches the same answer. Indexes without that file resolve as before. Some flows get shorter where a step becomes ambiguous. This is still a static approximation, not Ruby's lexical constant lookup.
