- Every application unit now records `metadata.container` (W-9, #759), and its graph node records the container `kind`. The kind is `web`, `jobs`, `database`, `shared` or `tasks`. Jobs also carry their `queue`. A job has an `adapter` only when it does not use the application's: a class-level `queue_adapter` override, which is now also recorded as `metadata.queue_adapter`, or a native Sidekiq worker. Mailers carry their `delivery` method, and models and tables their `database`. Framework, test, documentation and configuration units carry no container. The value depends only on the unit's type and metadata, so full and incremental runs publish the same container. See [Container attribution](docs/EXTRACTOR_REFERENCE.md#container-attribution).
