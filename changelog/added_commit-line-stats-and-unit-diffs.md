- The commit table records each listed file's `additions`, `deletions` and `hunks` (`[{old: [start, length], new: [start, length]}]`, git `-U0` style in the commit's own coordinates) with `hunks_truncated` (#804). A second patch walk over only the table's commits supplies them. `git_commit_table_line_stats` (default true) turns it off, and `git_commit_table_hunk_budget` (default 50000; at most 100 per file) bounds the hunks. Both settings are recorded in the table and decide its content, so incremental runs stay equivalent to a full run. Binary files have null counts.
- Change impact reports give each modified unit whose source moved a bounded `source_changes`: changed line ranges in each endpoint's annotated `source_code`, added and removed line counts, and `coverage` (`complete`, `truncated`, `too_large`; new budget `max_source_hunks`) (#802). `Woods::Impact::UnitDiff.compare(index_dir, unit:, from:, to:)` returns one unit's unified diff with context and both endpoints' line numbers, plus the facets, categories and metadata keys the report would record for it. Readers such as Woods Map draw diffs without comparing payloads themselves.
