- An incremental run decides whether a re-derived unit is unchanged before the method table, callback declaration sites and test examples are recorded, not after. Those three walk the unit's `source_code` with Prism and derive only from what the check compares, so a unit that comes out unchanged (most of a change's blast radius) skips them and keeps its published JSON byte for byte; the source line map, which depends on the file as it is now, is still recorded first. On a generated application with about 10,000 units, a one-file comment edit re-derives about 6,200 units, of which one is written: `register_and_write` dropped from about 1.35 s to about 0.94 s of a 9 s re-extraction phase, the remainder being the read and parse of each published unit for the comparison itself.
