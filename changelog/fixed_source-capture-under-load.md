- A full extraction on an unchanged tree no longer aborts with `Source-reference input was not captured` when the machine is under load. The source capture that runs before boot gave up after a fixed 10 seconds and kept only the files it had hashed by then. The walk visits `app/` before `lib/`, so a slow capture on a large application dropped late `lib/` files, and the source-reference pass then refused the run. The capture now gets the same 120-second ceiling as the publication recheck, in both the `woods-extract` launcher and an in-process `woods:extract`. The file and byte caps still bound its work. A capture that genuinely stalls past the ceiling still refuses publication, and an input that changes or vanishes during the run is still refused.
