- A writer that resumes after its lock was taken over can no longer change a published generation (#1004). Every writer now stages its payload in a private `payloads/.stage-<n>-<token>` directory, so a takeover never deletes or reuses another writer's directory. Promoting the stage to `gen-<n>`, writing `generation.json` and pruning old payloads run only while the writer proves it still owns the lock, under the same guard a takeover takes. An obsolete writer stops at that point, removes its own stage and reports `Could not publish generation … no longer held by this writer`; the successor's payload, the current generation and pinned readers are unchanged.
- The same fence now covers `woods:clean` (each deletion), the snapshot store write after a full run (now made only after a successful publish), and the self-map (`woods:self_map`), which also stages privately and keeps its lock fresh with a heartbeat. A writer that holds the index writer lock for a different directory than the one it writes now fails instead of publishing unfenced.
- A writer waiting for the lock no longer hangs when the holder is stopped inside that guarded step. `acquire` polls the guard and gives up within the caller's own wait (2 s for the MCP operator tools and `woods_reload`).
- A direct `Extractor#refresh`, `#extract_changed` or `#extract_all` call, whose caller holds no lock, now takes the index writer lock for its publish step instead of publishing unfenced. It waits as the rake tasks do (`WOODS_LOCK_WAIT`) and does not publish if the lock stays held.
- Promoting a stage to `gen-<n>` is now made durable (the `payloads/` directory is fsynced) before the generation marker is written.
