- Fall back to the PORO path for owned files whose extractor emits nothing (#672). Ruby under `config.unclaimed_ruby_paths` that a file rule owns, but for which every owning extractor produced no unit (helpers beside a serializer base, `module_function` or nested modules in a services directory, GraphQL batch loaders, custom fields, and a superclass-less `Resolvers::Base`), now becomes `poro` units marked `discovered_via: "owner_fallback"`. Full and incremental extraction make the same per-file decision. The GraphQL exclusion now uses the graphql extractor's own admission rule. Incremental extraction also drops a PORO unit whose class joins a class-discovered family through another file, and restores one when a reload drops it, so the result matches a full run. `skipped_files.json` keeps `rejected_by:<extractor>` only for files with no unit after the fallback.
