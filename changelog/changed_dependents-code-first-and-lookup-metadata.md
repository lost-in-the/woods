- `dependents` and `dependencies` list code first, then tests, schema, documentation and the rest, at each depth and under each row. In identifier order a model's first rows were its agent-instruction and documentation files, and a first page of 50 could hold no code. Rows, counts and `families` are unchanged; only their order and therefore the contents of each page.
- `dependents` and `dependencies` on an identifier the index lacks are now flagged as an error (`isError`, `_meta.error_code: not_found`, `_meta.suggestions`), as `lookup` already was. The structured payload still answers `found: false`.
- `lookup`'s Markdown, plain and Claude renderers leave out metadata values that say nothing: nil, empty strings, empty lists, and hashes holding only those (an association's `through: , through_db: , polymorphic: ,`; a callback's six empty side-effect lists). `false` and `0` are kept. The JSON renderer and the structured payload are unchanged.
- An incremental run writes the manifest's `counts` in the order a full extraction does, so `woods:stats` lists unit types the same way for both.
