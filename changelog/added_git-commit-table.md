- Each generation can now publish a commit table, `git_commits.json` (W-3, #753): every HEAD-reachable commit in a bounded window that touched an indexed path, newest first, with full sha, parents, author, committer date, subject (`message`), the rest of the message (`description`) and the files it touched with their status, plus a `paths` index from each indexed path to its commits, from which co-change is answered. The window and bounds are configurable (`git_commit_table_days`, default 365; `git_commit_table_limit`, default 5000 commits, with `truncated` when exceeded; `git_commit_table_files_limit`, default 100 files per commit, with `files_omitted`). Full runs write it; incremental and refresh runs keep it when its head, window, bounds and indexed-path digest are unchanged and rebuild it whole otherwise, so both publish the same table. It is absent, not empty, when the application has no readable git history. `Woods::PublishedIndex#git_commits` reads it (`commits_for`, `co_changes`, `commit` by short sha). `git_recent_commits` (default 5) raises the per-unit `metadata.git.recent_commits` count.
