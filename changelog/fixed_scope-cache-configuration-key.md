- The table of dispatch-rule scopes a process keeps between extraction runs was keyed on two configuration values, while the named matchers also read the documentation, config-file, GraphQL document, JavaScript, test-support, external-consumers and Rake task paths when they match. Changing one of those in the same process (a watch daemon, a long session) could leave a newly covered file classified by the old configuration and skipped. The table is now keyed on the whole extraction-shaping configuration fingerprint, so any such change starts a new table.
