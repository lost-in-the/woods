- The published lexical snapshot rebuilds only what a new generation changed. The index reader's `each_unit` takes a consumer table of decoded units by unit file and file identity (device, inode, size, modification time): a payload seeded from the generation before keeps every unchanged unit file as a hard link, so the retriever decodes only rewritten files, reuses the documents of unchanged units, and reuses the whole snapshot when no unit the index reads changed. Token-cache accounting is unchanged, every answer equals a cold build, and the reader's symlink and identity guards run before any reuse. On the 11,038-unit self-map a one-file-change refresh went from 1.62 s to 0.56 s and a no-op publication from 1.60 s to the cost of one stat per unit file.
