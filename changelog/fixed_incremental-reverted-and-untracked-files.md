- `woods:incremental` no longer refuses to run after an extracted edit is reverted. The default change set was only `git diff HEAD~1`, which describes the last commit and the working tree, not what the index holds: a reverted file left the diff while the index still carried the edit, and every later run failed with `Woods::SourceReferences::RebuildRequired` until a full extraction. A new file git did not track yet was ignored with exit 0, and deleting one that had been indexed left its unit behind. The default now also adds every file whose bytes no longer match the digest the published index records for it, and every recorded file that is no longer on disk, and prints how many it added. `CHANGED_FILES` and CI ranges are used as given.
