- `woods-mcp-start` now hands over to `woods-mcp` under the Ruby that ran it (`Gem.ruby`) instead of through the `woods-mcp` shebang, which could pick another Ruby off `PATH` and fail with `cannot load such file -- active_support/inflector`. A launcher started from a source checkout with `ruby -I <checkout>/lib exe/woods-mcp-start …` now carries that `lib` forward through `RUBYLIB`, keeping any existing entries, so the server no longer activates an installed Woods gem and fails with `Gem::ConflictError`. Launches through `bundle exec` and the packaged binstub were not affected.
