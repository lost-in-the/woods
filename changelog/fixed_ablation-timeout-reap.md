- The ablation harness's per-call timeout no longer spends its whole TERM grace on a child that already died. The timeout interrupts the executor's own `Process.wait2`, so a leader that exited on TERM stayed a zombie, and a zombie still answers `kill(0)` for its process group: a `ruby -e 'sleep 30'` call with a 0.2 s timeout returned after 2.2 s. The owned pid is now reaped inside the same poll loop that probes the group, which returns as soon as the group is really empty while a TERM-compliant descendant of an exited leader still gets the full grace to shut down before KILL. A probe the kernel refuses with `EPERM` (seen on macOS) now counts as alive and runs out the grace instead of escaping `call` and aborting the whole ablation run with the process still running. On Linux the probe also reads the group's members from `/proc` and ignores the ones already in state Z, so a descendant the dead leader orphaned, which only init can reap, no longer keeps the group "alive" until init gets to it.
