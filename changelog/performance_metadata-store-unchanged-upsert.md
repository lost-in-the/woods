- The SQLite metadata store no longer rewrites a row whose type and JSON text are unchanged: the upsert carries a `WHERE` clause, so an unchanged `woods:embed_incremental` issues no write and no journal fsync per unit (500 unchanged re-stores: 710 ms to 26 ms in the audit's paired measurement; re-measured in this change). `updated_at` on both metadata backends is now defined as the last content change, and the in-memory store keeps the earlier stamp across an unchanged re-store the same way. A key-order-only difference in the JSON text counts as a change.
