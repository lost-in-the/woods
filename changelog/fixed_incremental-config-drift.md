- Incremental extraction and `woods:refresh` refuse to build on a generation whose extraction-shaping configuration differs from this run's. A run that left out an initializer or loaded another environment used to publish a valid-looking generation without the facts that configuration produces (`reads_config` edges, `external_consumer` units, `exercises_route` edges). Each manifest now records `extraction_config`, one digest per setting in `Woods::Configuration::EXTRACTION_KEYS`; the refusal names the changed settings, never their values, and asks for a full `woods:extract`. A baseline written before this change warns and runs, and its next full extraction records the digests. The refusal is `Woods::ExtractionConfigChanged`, a `Woods::ExtractionError`. The watch daemon answers it with one full extraction in the same cycle instead of staying degraded until someone runs one by hand.
