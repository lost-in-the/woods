- One-file incremental extractions spend less time on work that does not depend on the change. On a generated application with about 10,000 units in packs, a one-file model edit dropped from about 24 s to about 18.5 s, an added model file from about 16 s to about 11.3 s, and a deleted one from about 25-26 s to about 19.5-20 s; on a generated application with about 9,000 units, a one-file service edit dropped from about 15.4-16.3 s to about 13.5-14.6 s. The changes:
  - A model edit re-runs the table extractor only to re-derive which model owns each table. With no schema dump or migration in the change set, the live schema is the one the published table units were read from, so their columns, indexes, foreign keys and primary key are reused instead of four schema queries per table. Ownership still comes from the live catalog, and a table the published units do not hold is read live.
  - The controller extractor builds its routes map and its route helper map on first use, so reconciling controllers in an incremental run no longer walks every route twice.
  - `DependencyGraph#pagerank` is memoized until the next registration or removal, so writing the graph and analysing it rank it once. Source and documentation references list typed identifiers without serializing the whole graph (`DependencyGraph#typed_identifiers`).
  - Source capture matches each path against the dispatch rules once per run instead of twice, and memoizes path relativization against the bundle's gem roots. The route extractor asks git only about named route files.
