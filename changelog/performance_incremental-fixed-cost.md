- Every extraction spends less time on work that does not depend on how many files changed. On a generated application with about 9,000 units, a one-file incremental took about 21 s (median of six runs) and now takes about 15.6 s; a full extraction dropped from about 52-60 s to about 45-47 s. The changes:
  - Git source filtering asks git in batches. Classifying a configuration source took two git processes per file: once at source capture, once at the publication recheck, and again in the skipped-files report and the configuration and route extractors. Each process starts as a fork of the extracting Ruby process, so on a large application one query cost tens of milliseconds. `GitSourceFilter#skip_reasons` and `#prefetch` answer a whole directory, or a whole candidate list, with one ignore query and one index query. A path neither ignored nor indexed is confirmed with the single-path query, so every answer is unchanged. The route extractor checks git only for named route files.
  - The controller extractor builds its routes map on first use, so reconciling controllers in an incremental run no longer walks every route.
  - `DependencyGraph#pagerank` is memoized until the next registration or removal, so writing the graph and analysing it rank it once. Source and documentation references list typed identifiers without serializing the whole graph (`DependencyGraph#typed_identifiers`).
  - Source capture matches each path against the dispatch rules once per run instead of twice, and memoizes path relativization against the bundle's gem roots.
