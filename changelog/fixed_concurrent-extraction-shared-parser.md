- `config.concurrent_extraction = true` no longer corrupts source-reference analyses or exhausts the database pool. Every extractor thread shared one `SourceReferences::MemoCollector`, whose underlying `Collector` keeps the record it is building in instance state, so two threads parsing at once interleaved each other's declarations and references; the memo now serializes its parses. The run also started one thread per extractor (42) against the ActiveRecord pool (5 by default), so schema-reading extractors could wait out `checkout_timeout`; threads are now a bounded pool no wider than the connections free when it starts (a connection the calling thread already leases doesn't count), each worker holds a connection only while an extractor runs, and with none free the extractors run on the calling thread. The flag stays off by default.
