- Phlex and ViewComponent `render` edges now name the component unit they reach instead of the name as written. A target is resolved the way the running app resolves it: `render TierGrid.new` inside `Billing::V2::ManagePage` targets `Billing::V2::TierGrid`; a Phlex Kit call (`Header(title: "x")`, `Ui::Header(...)`, or `menu.NavItem(...)` on a block argument) targets the Kit's component. An aliased constant (`Card = Ui::Card`) targets the component it names. Lookups read loaded constant tables only, so nothing is autoloaded.
  A helper call (`form_with`, `t`, `render partial("x")`) no longer produces a `render` edge. A capitalized render that names no component class produces no edge and is listed in the new `metadata.unresolved_renders` as `{ name:, reason: }`. Re-extract to replace the stored edges. A render of a component class the application does not define (a gem's component) produces no edge either and is listed in `metadata.external_renders` as `{ name:, gem: }`.
