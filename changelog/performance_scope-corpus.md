- Scoped retrieval and discovery (`codebase_retrieve` and `search` with `packages:`/`source_paths:`) no longer read every metadata record on each request. The retrieval pipeline keeps one scope corpus per store bundle (`Retrieval::ScopeCorpus`): in semantic mode an immutable copy of the in-memory metadata store's records, kept while the store's new `snapshot_version` stands (SQLite reports none and keeps the per-request read); in lexical mode the index's own units; and the Index Server keeps the scope facts of the loaded generation, read once from the published units. Scoped answers are unchanged. On the gem's 6,139-unit self-map a `lib/` scope answers in 77 ms instead of 460-540 ms (lexical) and 150-175 ms instead of 560-580 ms (semantic), an empty scope in 15-21 ms instead of 38-58 ms, and a scoped Index Server `search` in 18-22 ms instead of 536-747 ms (identifier) and 83-90 ms instead of 792-849 ms (deep source), with lower warm resident memory in every mode. `MetadataStore::Interface#snapshot_version` (nil for an adapter that tracks no changes) is the new adapter seam.
