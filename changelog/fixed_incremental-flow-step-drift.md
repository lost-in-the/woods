- An incremental run with `precompute_flows` now reassembles every controller whose published flow steps into a unit defined by a changed file, even when the dependency graph holds no edge from the controller to that unit (for example a lib class instantiated inside an action). Such a controller used to be carried forward with its old step lines, so its flow document drifted from what a full extraction writes (#945). The controllers come from the previous generation's flow inverse (`flows/by_unit.json`), or from its flow documents when an older generation has no inverse; an unreadable inverse or document stops the run rather than carrying a flow it cannot check.
