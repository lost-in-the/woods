- Job enqueue, service and mailer references now resolve through the lexical nesting at their call site, the way Ruby's constant lookup does: each enclosing class or module innermost first, then the innermost one's ancestors, then the top level. `PingJob.perform_in(...)` inside `class Shipment` used to record a `PingJob` edge that matched no unit when the job is `Shipment::PingJob`; it now targets `Shipment::PingJob`. A reference keeps its written name outside any class or module, after an explicit `::`, or when no candidate is a loaded constant. A job that enqueues itself by its bare name inside its namespace no longer gains a dangling self-edge.
