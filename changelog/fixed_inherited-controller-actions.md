- Controller actions defined outside the controller class are now indexed: an action from an included concern, from a module prepended out of another controller's file, or (when routed to the controller) from a base controller appears in `metadata[:actions]` and gets a request flow assembled from its defining body, with the controller's own before filters. Each action's owner, defining unit, file and line are recorded in `metadata[:action_sources]`, and a `:action_source` dependency edge to the defining unit makes an edit to that file re-extract the receiving controllers and rebuild their flows incrementally. Each controller also gains an `:inheritance` edge to an app-defined parent controller, so a routed action a base controller gains later reaches its subclasses; editing `ApplicationController` now re-extracts every controller and rebuilds their flows. **Behavior change:** an action is now admitted only when its method body is application source and its name is not a setter, so public methods a gem DSL defines on a controller (for example `expose(:widget)` readers and writers) are no longer actions and no longer get flows; unrouted public methods a base controller defines are not added to its subclasses.
