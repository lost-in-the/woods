- `CachingExtractor` records calls on cache stores a Ruby file obtains itself, not only `Rails.cache`. A store expression is `X.cache_store(...)`, `ActiveSupport::Cache.lookup_store(...)`, `ActiveSupport::Cache::*Store.new(...)`, or an `||`/`or` fallback with a store on either side (`@store = store || Connection.cache_store(namespace: ...)`). A receiver counts as a store when it is a variable or constant assigned from one, a method that returns one, an `attr_reader`/`attr_accessor` of a bound instance variable, a forwarder or alias of such a method, or a store expression chained directly. Its `read`, `write`, `fetch`, `delete`, and `exist?` calls appear in `cache_calls` with key, TTL, and options like `Rails.cache` calls, plus `store` (the receiver at the call site) and `store_origin` (the store expression it was first bound from), and count as low-level caching. A file whose only cache use is such a store is now a caching unit.
