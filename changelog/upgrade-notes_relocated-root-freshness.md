- `woods_status` source freshness now works for an index served from the same checkout under another path. Before, an index whose recorded root was not reachable (an application extracted at one path and read at another) always reported `unknown` with `source_root_unavailable`. The MCP reader now checks `WOODS_SOURCE_ROOT` when it is set. Otherwise, when the recorded root is not a directory, it checks the application that owns the served index directory: the nearest ancestor with `config.ru` or `config/application.rb`, never past the checkout that holds the index. It verifies the captured paths and bytes there. `root_source` has a new value, `re_resolved`. Clients that switch on `root_source` should accept it. A re-resolved root counts only when at least one captured file still has its captured bytes. Otherwise the result stays `unknown` with `source_root_unavailable` and `root_rejected: "no_captured_file_matches"`, never drift against an unrelated tree. Results from `woods_status` and `woods:source_status` now also list `scope` (the consumer scopes captured and the declared roots) and `exclusions` (skipped directories, hidden entries and the index output). History and Git enrichment are unchanged: they read the recorded root, and stay `unknown` when it is unreachable. A recorded root that is reachable is still checked as before.
