- `woods_status` reports `index.history.state` (`current`, `stale` or `unknown`) by comparing the HEAD recorded in the published generation with the live HEAD. A commit with no source change now shows history as stale even when source freshness is current. The live HEAD resolves through `Woods::GitProvenance`, so linked worktrees and `WOODS_GIT_DIR` behave as they do during extraction; the repository is the application root recorded in the generation, never the one enclosing the index directory. A missing or unreachable root, or a directory Git cannot resolve, is `unknown`, never stale. `head_git_sha` and `git_sha_matches_head` use the same root.
