- Every recorded-pid check now gives the same four answers: alive, dead, zombie or unknown (#1002). A pipeline lock, a supervision record or an MCP task whose same-host process has exited but was never reaped (a container whose PID 1 does not reap) is now treated like a dead one: the lock is taken over at once, the record can be pruned and the task is marked `failed`. Unknown liveness (a pid on another host, or `EPERM` with no readable `/proc` status) never triggers a takeover on its own; the lock still expires by age, and a task still fails after the 24-hour grace window.
- The `pipeline_extract` and `pipeline_embed` operator tools now lock the index directory the server serves and write into that same directory. They used to lock `config.output_dir`, which could differ from where the server was reading.
