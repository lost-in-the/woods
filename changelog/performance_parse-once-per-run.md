- Every analysis that reads a unit's Ruby source during a run (lexical nesting, the method table, callback sites, test examples, the PORO walker, scope and callback analysis, and the rest) now shares one Prism parse and one normalized syntax tree per distinct source, through a per-run `Woods::ParseCache`. On the 10,000-unit testbed a full extraction made ~36,000 parse requests for ~11,000 distinct sources; the model and controller extractors paid most of the repeats. The cache keeps a small window (`config.parse_cache_source_bytes`, 1 MB of source by default, `0` to disable) because holding every tree for the run doubled GC marking time and gave the saving back. `app_source?` also stops expanding paths that are already absolute. Published payloads are byte-identical. About 2s off a 47s full extraction on the testbed; `WOODS_PROFILE=1` logs the run's parse and reuse counts.
