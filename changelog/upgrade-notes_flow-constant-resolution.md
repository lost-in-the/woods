- Flow target resolution changed (#967), and `trace_flow` clients can see it in three places. Run a full extraction to refresh precomputed flows.
  - **Some flows are shorter.** With `precompute_flows` on, a call whose single-segment receiver matches one app unit by short name, while the booted app already defines a top-level constant of that name (`I18n.t` beside `Lint::I18n`), is no longer expanded into the app unit. The step stays in its caller's `operations` with `ambiguous_candidates`, and the steps that used to follow it are gone. Rooted calls (`::Billing::Invoice.create!`) now expand where they used to be dropped, so some flows gain steps too.
  - **`ambiguous_candidates` can name a constant that is not a unit.** The top-level candidate comes first and is spelled rooted, for example `["::I18n", "Lint::I18n"]`. `lookup` does not resolve `::I18n`; it is a constant the app defines (often a gem's), not an indexed unit. Every other entry is still a unit identifier.
  - **A new optional artifact, `flows/top_level_constants.json`,** is published beside `flow_index.json` as `{ "top_level_constants": [...] }`. Flow assembly without Rails (`trace_flow` on demand, `diagram`, `woods:flow`) reads it so it reaches the same answer as the precompute. Indexes without it resolve as before. `woods:validate` reports it if it is malformed, and a malformed file makes `trace_flow` answer `corrupt_artifact` for flows it assembles on demand.
