- A model callback's `side_effects[:jobs_enqueued]` now names each job the way Ruby resolves it inside the class that defines the callback, matching the model's enqueue edges. `PingJob.perform_in(...)` in a callback of `Fleet::Shipment` used to be recorded as `PingJob`; it is now `Fleet::Shipment::PingJob` or `Fleet::PingJob`, whichever is loaded, and stays as written when neither is.
