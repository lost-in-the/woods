- `search` ranks identifier matches by match quality: the exact identifier, then an exact short name (the last `::` segment, a table's name after `table:`, a path segment, a route's path rather than its HTTP verb), then prefixes, then other matches, shorter names first. The order no longer depends on type directory or summary order, so it is stable across generations of the same source, and a broad query no longer pushes the exact name or its table off the page. `IndexReader#search` takes `max_scan:` for one call, so an in-process caller can size the deep-field budget to the index, and a deep search reports `scan: { scanned_units:, candidate_units: }`. The MCP tool keeps `WOODS_SEARCH_MAX_SCAN`.
