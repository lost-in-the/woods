- `woods:incremental` now says why a run became a full extraction: it lists each restart input that forced it (the first ten, then a count) with its source, a commit in the range, the working tree, or `CHANGED_FILES`. The default change set is unchanged: `git diff HEAD~1` compares the last commit's parent with the working tree, so it includes staged and unstaged changes to tracked files but not untracked files. That is now documented in `docs/INCREMENTAL_EXTRACTION.md` and in `rake -D woods:incremental`, and the task prints a note when an uncommitted change forced the full run. Set `CHANGED_FILES`, or commit or stash local changes, to keep them out (#948).
