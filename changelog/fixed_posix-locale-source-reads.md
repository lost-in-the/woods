- Host source is now read as UTF-8 whatever the process encoding. A bare `File.read` tags bytes with `Encoding.default_external`. A Rails boot sets that from `config.encoding` (UTF-8 by default), so a booted extraction under `LC_ALL=C` already read source correctly. Code that reads without that boot, or a host whose `config.encoding` is not UTF-8, got US-ASCII or that encoding instead, and the first regex or Prism call on a multibyte byte raised, so the extractor skipped the file. Every extractor and the incremental re-add of a moved class now read through `Woods::SourceFile.read`. A Solid Queue `recurring.yml` with multibyte YAML is read the same way.
- A source file holding bytes that are not valid UTF-8 now keeps its unit on every host, UTF-8 included. The bytes are replaced with U+FFFD; before, the first scan raised and the unit was dropped. The `lib/` extractor is the exception: it still refuses invalid source, as before.
