- Extraction no longer drops units for multibyte source files under a POSIX locale (`LANG=C`, the default in a plain container image). A bare `File.read` tagged host source US-ASCII, so an em dash in a comment made the first regex or Prism call raise and the extractor skipped the file without a trace; i18n and package units kept an invalid string instead. Host source is now read as UTF-8 by `Woods::SourceFile.read` in the model, controller, service, serializer, job, validator, policy, Pundit, decorator, manager, migration, rake task, scheduled job (every schedule format, including Solid Queue `recurring.yml`), i18n, configuration, state machine, database view, event, test mapping, package, factory, view template and Rails/gem source extractors. Bytes that are not valid UTF-8 are replaced with U+FFFD rather than dropping the unit. A UTF-8 host sees no change.
