- A model whose polymorphic `belongs_to` declares `inverse_of` (including the association `delegated_type` defines) is extracted again. Reading the association asked Active Record to compute the inverse, which it cannot do for a polymorphic association, and the error dropped the whole model with only a warning while the run reported success. The association now publishes the declared `inverse_of` name. An association that raises any error while its metadata entry is built is now skipped with a warning, where before only a `NameError` was; that rescue covers the association metadata, not every pass that reads associations.
