- `dependents` adds a server-side family for every row and a `dependent_counts` summary over the whole traversal (not the page). Each row but the root carries `family`: `code`, `tests`, `schema`, `docs` (agent instruction files such as `AGENTS.md` are `doc` units) or `other`; the families add up to `dependent_counts.total`. `dependent_counts.headline` is a new number: it counts `code` rows only, with `mapped_tests` beside it. A mapped test is a `test_mapping` row reached through `test_coverage`; it also carries `mapped_test: { via: "test_coverage", direction: "test_to_subject" }` and text renderers mark it "(Mapped test)". Mapped tests stay listed, so the rows a call returns are unchanged. The new `config.reverse_includes_tests` (default `false`, or `WOODS_REVERSE_INCLUDES_TESTS` for a server without the host initializer; an unrecognized value warns and is ignored) adds mapped tests to the headline; it is read per query, never by extraction, so changing it needs no re-extraction. `woods_status` reports it as `features.reverse_includes_tests`. After a budget cutoff `exact` is false, `bound` is `lower_bound`, and text renderers print `at least`. A client that compared its own row count with another number should read `headline` as "recorded code dependents", not as the number of rows. `dependencies` is unchanged.
