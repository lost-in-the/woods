- `CachingExtractor` scans in linear time. The fragment-cache pattern rescanned the rest of a line from every `cache` token, which is polynomial on Rubies without regex memoization: a single 300 KB line of repeated `cache ` took 77 seconds on Ruby 3.0. It now reads tokens (backslash pairs, quoted strings, single characters) and stops each scan at the next `cache` token outside a string. Checking bare `cache_key` arguments against cache call ranges is a binary search rather than a scan of every call.
- A fragment cache key whose string mentions `cache` (`cache [record, "cache me"] do`) is read as one call at the outer `cache`, and a `cache ... do` inside another cache call's arguments (`Rails.cache.fetch([id, "cache me do"])`) is no longer reported as a fragment cache.
