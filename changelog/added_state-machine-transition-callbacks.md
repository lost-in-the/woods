- State machine units publish `transition_callbacks` (#796): each `before_transition`, `after_transition`, `around_transition` and `after_failure` call as `{ kind, on, from, to, method, block, side_effects }`. The scope is the literal one and is never evaluated; a non-literal field stays empty and is named in `unresolved`. A symbol method defined in the model file or an included `app/models` concern gets the same side-effect analysis as model callbacks (columns written, jobs enqueued, services, mailers, operations); a block, a proc or a method defined elsewhere is marked `unanalysed`. A schema change now re-runs the state machine family during incremental extraction, since columns written depend on the model's columns.
