- A model with a `has_many :through` or `has_one :through` association now publishes a `through_chain` dependency edge to every model the association's reflection chain passes through that it does not already reference. Its published association metadata (the foreign key, the target) is read from those reflections, so `Owner has_many :parts, through: :bridges`, where Bridge's own `:parts` runs through Link, depends on Link. The edge puts Owner one hop from Link, so a `:structural` incremental run re-extracts it when Link changes; before, Owner kept the old foreign key (#961). A chain Rails cannot reflect on adds no edge.
