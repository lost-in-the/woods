## Context you can trust (don't re-derive)
- **Woods** is a Ruby gem (repo at `/Users/leah/lost-in-the/woods`) that extracts a structural index of a running Rails app. Key artifact: `tmp/woods/dependency_graph.json` (contains `file_map` = file→unit, `nodes` = unit→{file_path,type}, `reverse` = unit→[dependent names], `pagerank` = unit→score). It also writes per-unit JSON profiles.
- It has **full extraction** (`rake woods:extract` — boots Rails, eager-loads, ~minutes, ~6,500 units for a large app) and **incremental extraction** (`rake woods:incremental` — re-extracts only changed files).
- There's a **`woods-admin` MCP server** exposing tools like `dependents`/`lookup` that return a unit's dependents (by name), counts, and PageRank — queried by unit NAME.
- The admin app (`/Users/leah/work/compose-dev/admin`) wires Woods in; there's a scheduled Buildkite `woods-sync` step that runs `woods:extract` on `main`.
